**Цель — вернуть Джарвису надёжную работу через Hermes и Codex на имеющейся Pro Full.** Состояние зафиксировано 10 сентября 2026 года.

## Что установлено

| Проверка | Результат |
| --- | --- |
| Pro Full → Hermes → Codex: Astra, Sol, Terra | Ошибки перегрузки по наблюдению владельца |
| Pro Full → официальный ChatGPT Work: GPT-6, GPT-5.6 | Плашка перегрузки |
| Pro Full → официальный Work в Edge: GPT-5.5 | Ответ получен |
| Pro Full → Hermes → Codex: GPT-5.5 | Проверка ещё не подтверждена |
| Pro Full → обычный разговор | Работает |
| Pro Light → Work | Работает в той же среде |

Один домашний ноутбук, одна сеть и VPN. В Edge и Яндексе картина та же. Переключение учёток выполнено штатной функцией ChatGPT. Ошибка Full в браузере сохраняется при выключенном Hermes.

**Это зависимость от сочетания учётки, модели и маршрута.** Физический пул серверов, блокировка учётки и точная причина на стороне провайдера не доказаны. Отдельная короткая проверка в новом Work-чате поможет проверить влияние состояния старого чата.

## Что показали журналы

- 151 основная ошибка перегрузки: 102 Sol и 49 Astra; более позднее наблюдение Terra в этот счётчик не входит.
- Ещё 11 ошибок перегрузки — во вспомогательных запросах.
- Повторы ограничены тремя попытками. Бесконечный перебор учёток по этим данным не установлен.
- 1 987 успешных вызовов были в подробном окне журналов. Исторически доступность была переменной.
- В 10:33 по Москве 10 сентября оставался 41% недельного лимита. Это снимок одного показателя, а не доказательство отсутствия любых ограничений.
- После отказов генерации новой сводки активная история сокращалась с 850 до 82 и с 328 до 102 сообщений. Удаление полного архива этим не доказано.

Полные частные журналы и экспорт сессии сохранены у владельца. Здесь опубликованы проверенные выдержки, счётчики и ссылки. Нельзя складывать разные окна наблюдений в общий процент отказов.

## Практический путь восстановления

1. В существующем соединении Hermes с Full проверить `gpt-5.5`: ответ модели → один безопасный инструмент чтения → продолжение модели по результату.
2. Если цикл проходит, проверить явные назначения моделей у исполнителей, вспомогательные задачи, сжатие и резервные маршруты. Рабочая главная модель не гарантирует, что они тоже переключились.
3. Перед возобновлением длинной задачи сохранить её незавершённый шаг и уже полученные результаты инструментов. Для работающего процесса проверить реальное состояние, затем продолжать.
4. В тестовой среде проверить поведение после исчерпания повторов и отказа сводки. Завершённые действия не должны выполняться повторно без решения о допустимости повтора.

Подробные критерии и границы проверки: [RECOVERY.md](RECOVERY.md).

Владелец уточнил: непрерывная работа была настроена до первого Provider Error; рассогласование учёта задач и преждевременные финалы начались после него. Последующие окончания ходов сами по себе не устанавливают первичную причину. Точный первый переход состояния ещё требует проверки.

**Джарвис пока не объявлен восстановленным.** Успешный ответ GPT-5.5 в браузере — полезный найденный маршрут для проверки, но не доказательство работающего цикла Hermes.
